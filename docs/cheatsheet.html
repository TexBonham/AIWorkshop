The 9 habits

#HabitIn a browser chat
1Context firstStart with a project brief: what the code is, what "done" means, what not to touch. Put it in the Project's instructions.
2Symptom, not diagnosisSay what you saw and expected. Don't guess the cause for it.
3Reproduce, paste real outputExact wrong output, red test lines. Text, not screenshots.
4Plan + assumptions before code"List your assumptions and a plan. Don't write code yet." Correct, then approve.
5One intention per requestStep sized to what you can check. No changes you didn't ask for.
6Verify before you believe"Fixed" is a claim, not evidence. Tests or checklist decide. Report the real result.
7Read the diff, own the decisionYou're the reviewer. Make it argue against its own choice.
8Fresh chat when context rotsLong chats drift and cost more. New task = new chat.
9Budget your messagesPlan every message. Each "still broken" costs one.

Plan → approve → one step → check → report back.

Prompt skeletons

#SkeletonUse it to…
0Project briefset the rules once: plan first, smallest change, only app.js, never claim "fixed"
1Report a buggive what you did / saw / expected + red test lines. No code yet.
2Assumptions + planget every assumption and a numbered plan before any change
3Approve (and correct)fix wrong assumptions, approve specific steps, see only changed lines
4Report backpaste the red lines (or "all green") after testing
5Complaint → specgive the complaint word for word + your examples; ask what's undecided
6Argue against itget the strongest case against and one alternative. No code.
7Build from a briefbrief + acceptance checks; assumptions and plan first, then one build
8Fix roundlist only the failing checks; "don't change anything that works"
